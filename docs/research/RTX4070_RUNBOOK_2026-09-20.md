## Step 2 — THE BIG ONE: 2 denoising steps (~4 min)

This is D2. DiT time is exactly linear in step count, so 4→2 halves it:
`8.474913 → 4.237457 s` per 250-frame equivalent.
Projection: **21.290295 → 17.052839 s = 14.66 FPS (+24.85%)**.

```bash
PYTHONPATH="$NEW_DEPS" .venv/bin/python benchmarks/pro_quantization_v2_20260918/run.py \
  --policy benchmarks/pro_30fps_20260919/policies/combined_fp16_sage_fp8.json \
  --fixtures benchmarks/pro_quantization_v2_20260918/fixtures.json \
  --fixture-id indian150-a --seed 50 --frames 250 --repeats 1 \
  --sampling-steps 2 --timestep-variant distilled_aligned \
  --latency-detail off \
  --output "$OUT/steps2-r01"

.venv/bin/python -c "
import json
b=json.load(open('$OUT/rebaseline-r01/results.json'))['runs'][0]
c=json.load(open('$OUT/steps2-r01/results.json'))['runs'][0]
s=json.load(open('$OUT/steps2-r01/results.json'))['sampling_schedule']
print('schedule        ', s['resolved_post_shift_timesteps'])
print('baseline  FPS   ', round(b['useful_fps'],4))
print('2-step    FPS   ', round(c['useful_fps'],4))
print('gain            ', round(c['useful_fps']/b['useful_fps']-1,4))
print('DiT  base/2step ', round(b['stage_seconds']['dit'],3), round(c['stage_seconds']['dit'],3))
print('DiT ratio (want ~2.0):', round(b['stage_seconds']['dit']/c['stage_seconds']['dit'],3))
"
```

**The load-bearing check is the DiT ratio.** If `stage_seconds.dit` does not
roughly halve, the linearity assumption is wrong and the whole D2 projection
collapses — report that before looking at FPS.

**Expected schedule:** `[1000.0, 625.0, 0.0]`. If you see `[1000.0, 833.33, 0.0]`
you omitted `--timestep-variant distilled_aligned`.

**Speed is not acceptance.** 2-step sampling changes the input distribution
reaching each trained timestep. Nothing is promotable until Step 5.

## Step 5 — Quality gate (PROMOTION BLOCKER — run before believing any of the above)

Nothing in Steps 2–4 is promotable until this clears. Two retained quality arms
already **disagree in sign** on the current candidate: the 1,500-frame
`extended-r01` arm shows it *better* on own-crop (0.7404 → 0.7495), while the
45-window `new-speech-correction-r01` arm shows it worse (0.7629 → 0.7450).

```bash
# Four-seed raw mouth review of the 2-step arm against the 4-step baseline.
for SEED in 50 51 0 1; do
  for ARM in "4:--latency-detail off" "2:--sampling-steps 2 --timestep-variant distilled_aligned"; do
    STEPS="${ARM%%:*}"; FLAGS="${ARM#*:}"
    PYTHONPATH="$NEW_DEPS" .venv/bin/python benchmarks/pro_quantization_v2_20260918/run.py \
      --policy benchmarks/pro_30fps_20260919/policies/combined_fp16_sage_fp8.json \
      --fixtures benchmarks/pro_quantization_v2_20260918/fixtures.json \
      --fixture-id indian150-a --seed "$SEED" --frames 250 --repeats 1 \
      --save-raw $FLAGS \
      --output "$OUT/quality-steps${STEPS}-seed${SEED}"
  done
done
```

Then run the existing `review.py` / sync-check tooling over those directories,
and report per-window deltas at **both lag 0 and per-variant best lag** — a run
mean at lag 0 alone is what produced the contradictory readings above.

**Seeds are NOT comparable across step counts.** A fresh full `randn` is drawn
per step, so the generator stream differs. Compare distributions, not paired
seeds.

## Known limitation: sweep.py cannot A/B the step count

`sweep.py` forwards `--sampling-steps` to **both** roles, so it runs a paired
comparison *at* a fixed step count — it cannot compare 4-step against 2-step.
That was deliberate (an arm differing on one side only is not controlled), but it
means the D2 promotion sweep has to be assembled from direct `run.py` calls, as
in Step 5.

`sweep.py` IS the right tool for a policy A/B at fixed steps, e.g. cross-attention
q/o with three fresh processes per seed/role:

```bash
PYTHONPATH="$NEW_DEPS" .venv/bin/python benchmarks/pro_quantization_v2_20260918/sweep.py \
  --policy benchmarks/pro_30fps_20260919/policies/combined_fp16_sage_fp8_crossqo.json \
  --reference-policy benchmarks/pro_30fps_20260919/policies/combined_fp16_sage_fp8.json \
  --fixture-id indian150-a --seeds 50 51 0 1 --repeats 3 --frames 250 \
  --candidate-pythonpath "$NEW_DEPS" --reference-pythonpath "$NEW_DEPS" \
  --output "$OUT/sweep-crossqo-r01"
```
